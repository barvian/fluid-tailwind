## Basic usage

<Resizer client:load height="h-32">
  <button class="bg-sky-500 hover:bg-sky-400 @fl-lg/2xl px-fl-4/8 py-fl-2/3.5 text-fl-sm/xl rounded-full font-semibold text-white">Fluid button</button>
</Resizer>
```html mark="px-fl-4/8 py-fl-2/3.5 text-fl-sm/xl"
<button class="bg-sky-500 px-fl-4/8 py-fl-2/3.5 text-fl-sm/xl ...">Fluid button</button>
```

Make a utility fluid by adding the `-fl` suffix. Fluid utilities scale
between their `start/end` values when the viewport is between the start and end breakpoints
(by default these are the smallest and largest breakpoints).

## Configuration

### Custom default breakpoints

The default start/end breakpoints can be configured in your theme:

```css title="app.css" ins={3-4}
/* ... */
@theme inline {
  --fluid-default-start-breakpoint: 20rem;
  --fluid-default-end-breakpoint: var(--breakpoint-xl);
}
```

## Advanced

### Override breakpoints per-element

You can override the default start/end breakpoints on an element with
the included `fl` utility. For example:

<Resizer client:load height="h-32">
  <span class="text-slate-900 dark:text-slate-100 font-semibold @fl-xl/2xl text-fl-base/4xl text-center block">Quick increase</span>
</Resizer>
```html mark="fl-md/lg"
<h1 class="fl-md/lg text-fl-base/4xl">Quick increase</h1>
```

You can omit either start or end breakpoint to use your [defaults](#custom-default-breakpoints):

<Tip.Good>Set start breakpoint to `md`, end breakpoint to default</Tip.Good>
```html mark="fl-md"
<div class="fl-md text-fl-base/4xl">
```

<Tip.Good>Set end breakpoint to `lg`, start breakpoint to default</Tip.Good>
```html mark="fl/lg"
<div class="fl/lg text-fl-base/4xl">
```

### Negative values

When using the built-in negative prefix, Tailwind only negates the start value.
To negate both values, add a dash before the end value as well:

<Tip.Good>Negating a fluid utility</Tip.Good>
```html mark=/\(\-)5/
<div class="-mt-fl-3/-5">
```

### Container queries

You can make fluid utilities scale between the nearest `@container` widths rather than breakpoints by using the `@fl` utility:

```html mark="@fl-md/lg"
<h1 class="@fl-md/lg text-fl-base/4xl">Relative to container</h1>
```
{/* <Tip.Info>This may look confusing if you use [named containers](https://tailwindcss.com/docs/responsive-design#named-containers). Sorry about that; there's only so many ways to pass data into Tailwind. In general, when you see the fluid `fl` keyword, you know the `/` denotes a start/end pair.</Tip.Info> */}

Just like the `fl` utility, both start and end containers are optional and will use your [defaults](#custom-default-containers) if unset.

<Tip.Good>Set end container to `lg`, start container to default</Tip.Good>
```html mark="@fl/lg"
<div class="@fl/lg text-fl-base/4xl">
```

#### Custom default containers

The default containers can be configured in the same way as breakpoints.

```css title="app.css" ins={3-4}
/* ... */
@theme inline {
  --fluid-default-start-container: 5rem;
  --fluid-default-end-container: var(--container-xl);
}
```

### Combining with media queries

To really get crazy, you can combine fluid utilities with
container or media queries, as such:

<Resizer client:load height="h-32" tooNarrowClass="xl:hidden">
  <span class="text-slate-900 dark:text-slate-100 font-semibold italic ~@lg/2xl:~text-base/4xl @2xl:~@2xl/4xl:~text-4xl/base text-center block">Whoa!</span>
</Resizer>
```html
<h1 class="fl/md text-fl-base/4xl lg:fl-lg lg:text-fl-4xl/base">Whoa!</h1>
```

Here's how this works:
1. We scale our font-size between `base` and `4xl` between our smallest and `md` breakpoints
1. We scale in the opposite direction between our `lg` and largest breakpoints

## Integrations

### tailwind-merge

`fluid-tailwind` officially supports [tailwind-merge](https://github.com/dcastil/tailwind-merge) via a plugin:

```sh frame="none"
npm install --save @fluid-tailwind/tailwind-merge
```

For best results, include it after any other [tailwind-merge plugins](https://github.com/dcastil/tailwind-merge/blob/v2.3.0/docs/configuration.md#using-tailwind-merge-plugins):

```js mark=", withFluid"
import { extendTailwindMerge } from 'tailwind-merge'
import { withFluid } from '@fluid-tailwind/tailwind-merge'

export const twMerge = extendTailwindMerge(/* ... */, withFluid)
```
